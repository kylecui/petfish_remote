# 开发项目经验沉淀——给胖鱼伙伴团队的反馈

> 来源：petfish-remote 项目首轮 OpenCode 开发实践（2026-05-08）
> 背景：运维团队已在 ops 项目模板中加入"经验沉淀"原则。本文档从开发视角提出补充建议。

---

## 1. 开发项目也需要经验沉淀，但形态不同

运维的经验沉淀偏"操作规范"——同类操作反复发生，沉淀"怎么做"。
开发的经验沉淀偏"认知校准"——代码写一次就定了，沉淀"为什么这样"和"哪里有坑"。

建议在 `project-initializer` 的 code 类型模板中，生成的 AGENTS.md 预留以下两个段：

```markdown
## Development Gotchas

<!-- 记录代码库中非代码自解释的约定、已知陷阱、关键设计约束 -->

## Architecture Decisions

<!-- 重大技术选型和设计决策的简要记录，或指向 docs/ 下的完整 ADR -->
```

## 2. 从具体 bug 中抽象出的通用原则

以下三条从 petfish-remote 实际问题中提炼，适用于所有开发项目：

### 2.1 Scaffold 代码要么接入要么删除

**来源**：PolicyEngine 完整实现了 evaluate() 逻辑，TaskManager 构造函数接收了它，但用 `void this.policyEngine` 跳过了调用。从外部看，这段代码像是有意设计（类型正确、参数完整），实际是未完成的 scaffold。

**原则**：scaffold 阶段的占位代码必须带有明确标记（`// TODO: wire PolicyEngine` 或 `throw new Error('not implemented')`）。如果代码看起来像是接入了但实际没有，后续开发者（包括 AI agent）会误以为功能已生效，不会去修复它。

**建议写入开发项目模板的 AGENTS.md**：
> 发现 `void this.xxx`、空方法体、`// @ts-ignore` 等绕过模式时，视为架构缺陷而非有意设计，主动向用户报告。

### 2.2 状态枚举与转换守卫同步实现

**来源**：TaskStatus 定义了 9 个状态，实际只用了 5 个，且 `updateStatus()` 接受任意状态转换——可以从 `completed` 回到 `running`。

**原则**：定义状态枚举时，必须同时定义合法转换表。终态必须显式标记为不可出站。未实现的状态不要提前定义——它们会制造"看起来支持但实际不支持"的误解。

**建议写入开发项目模板的 AGENTS.md**：
> 修改状态枚举时，同步更新转换守卫表。新增状态前确认调用方会设置它。

### 2.3 多平台系统在渲染边界做平台分发

**来源**：OutputBatcher 默认使用 telegramRenderPolicy（4096字符截断），即使目标是 Feishu（30000字符限制）。feishuRenderPolicy 已经写好但没有被使用。

**原则**：跨平台系统中，IO 边界（渲染、发送、接收）是平台差异的天然分界线。在这些边界点必须做平台检测和分发，而不是依赖默认值。

**建议写入开发项目模板的 AGENTS.md**：
> 新增平台适配器时，检查所有 IO 边界（消息发送、输出格式化、长度截断）是否有平台分发逻辑。

## 3. 对经验沉淀机制本身的建议

### 3.1 开发项目的沉淀触发时机

运维项目是"每轮部署或运维完成后"触发沉淀。开发项目建议改为：

- 完成架构审查后（如本次 P1/P9/P13 修复）
- 修复了一个"看起来不是 bug 但其实是"的问题后
- 新增平台/适配器/集成点后

不建议每次代码提交都触发——开发中大量变更是增量的，不产生新的"认知"。

### 3.2 沉淀目标的区分

| 内容类型 | 目标位置 | 判断标准 |
|---------|---------|---------|
| Agent 必须第一时间知道的约束 | AGENTS.md | 违反会导致 bug，且代码本身无法自解释 |
| 架构选型及其理由 | docs/ 下 ADR 或架构文档 | 篇幅长，需要上下文才能理解 |
| 一次性排查过程 | 不沉淀 | 问题已解决，不会再发生 |
| 通用模式/反模式 | 反馈给模板层 | 不依赖具体代码库 |

### 3.3 避免 AGENTS.md 膨胀

运维项目的 AGENTS.md 容易因为持续沉淀而膨胀。建议设定上限：Development Gotchas 段不超过 10 条。超过时，审视哪些已经通过代码改进（如加了守卫、加了类型约束）变得不再需要文字提醒，移除它们。
